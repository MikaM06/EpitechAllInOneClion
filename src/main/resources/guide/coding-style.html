Epitech C Coding Style

Quick reference of the Epitech C coding style. Rules marked [Banana] are checked automatically by epiclang. Violations are graded by severity: Major, Minor and Info.

Shortcuts: Ctrl+Shift+H header, Ctrl+Shift+L check file, Ctrl+Alt+Shift+L check project, Ctrl+Shift+S this guide.

O – Files organization

C-O1 – Contents of the repository

No compiled (.o, .a, .so, binaries), temporary (*~, #*#) or unnecessary files in the repository.

C-O2 – File extension

Sources in C must only have .c or .h extensions.

C-O3 – File coherence [Banana]

A file groups functions related to the same thing. At most 10 functions per .c file, including at most 5 non-static functions.

C-O4 – Naming files and folders

Names are in English, clear, in snake_case.

G – Global scope

C-G1 – File header [Banana]

Every .c, .h and Makefile starts with the Epitech header. The project name and description need at least 2 characters. Use Ctrl+Shift+H to generate it.

/*
** EPITECH PROJECT, 2026
** mini_printf
** File description:
** display formatted output
*/

C-G2 – Separation of functions [Banana]

Exactly one empty line between two function implementations.

C-G3 – Indentation of preprocessor directives [Banana]

Directives are indented according to their conditional nesting level.

#ifndef MY_H_
    #define MY_H_
    #include <stddef.h>
#endif /* MY_H_ */

C-G4 – Global variables [Banana]

Global variables are forbidden; only global constants are allowed.

C-G5 – include [Banana]

#include only header files (.h), never .c files.

C-G6 – Line endings [Banana]

Line endings are UNIX style (\n), never \r\n. No backslash-newline sequences.

C-G7 – Trailing spaces [Banana]

No trailing spaces or tabs at the end of a line.

C-G8 – Leading / trailing lines [Banana]

No empty line at the beginning or at the end of a file.

C-G9 – Constant values

Non-trivial constants are defined with a macro or a global constant, not written as magic numbers.

C-G10 – Inline assembly [Banana]

Inline assembly is forbidden.

F – Functions

C-F1 – Coherence of functions

A function does one single thing.

C-F2 – Naming functions [Banana]

Function names are in English, in snake_case, and describe an action (verb).

int count_words(char const *str);
int CountWords(char const *str);

C-F3 – Number of columns [Banana]

A line never exceeds 80 columns (a tab counts as several columns).

C-F4 – Number of lines [Banana]

The body of a function never exceeds 20 lines (braces excluded).

C-F5 – Arguments [Banana]

A function takes at most 4 parameters.

C-F6 – Functions without arguments [Banana]

A function without parameter must be prototyped with void.

int main(void)
int main()

C-F7 – Structures as parameters [Banana]

Structures are passed by pointer, never by copy.

void print_point(point_t const *p);
void print_point(point_t p);

C-F8 – Comments inside a function [Banana]

No comments inside a function body. Comment above the function instead.

C-F9 – Nested functions

Nested functions are forbidden.

L – Layout inside a function scope

C-L1 – Code line content [Banana]

One statement per line. No assignment inside a condition, a return or another declaration.

fd = open(path, O_RDONLY);
if (fd == -1)
    return 84;
if ((fd = open(path, O_RDONLY)) == -1) return 84;

C-L2 – Indentation [Banana]

Indent with groups of 4 spaces. Tabs are forbidden for indentation.

C-L3 – Spaces [Banana]

One space after keywords (if, while, for, return...), after commas, and around binary/ternary operators. No space between a function name and its (. sizeof uses parentheses. Never several spaces in a row for spacing.

for (int i = 0; i < len; i++)
for(int i=0;i<len;i++)

C-L4 – Curly brackets [Banana]

Opening braces of control structures are on the same line as the condition; closing braces are alone on their line (except before else / while of a do-while). A function body's opening brace is alone on the line after the prototype.

int my_abs(int nb)
{
    if (nb < 0) {
        return -nb;
    } else {
        return nb;
    }
}

C-L5 – Variable declarations [Banana]

Variables are declared at the beginning of the function, one declaration per line.

C-L6 – Blank lines [Banana]

One blank line separates the variable declarations from the rest of the function. No other blank line inside a function.

V – Variables and types

C-V1 – Naming identifiers [Banana]

Variables, functions, typedefs in snake_case; macros and enum constants in UPPER_SNAKE_CASE. Typedef names usually end with _t.

C-V2 – Structures

Structures group coherent data only.

C-V3 – Pointers [Banana]

The pointer symbol * is attached to the variable name, not to the type.

char *str;
char* str;

C – Control structures

C-C1 – Conditional branching [Banana]

A conditional chain (if / else if / else) has at most 3 branches, and nesting must stay shallow: split into functions instead.

C-C2 – Ternary operators [Banana]

Ternaries must stay simple: never nested, no side effects, branches must differ.

C-C3 – goto [Banana]

goto is forbidden.

H – Header files

C-H1 – Content [Banana]

Headers contain only prototypes, macros, types, global constants and static inline functions. Prototypes and typedefs live in headers, not in .c files.

C-H2 – Include guard [Banana]

Every header is protected against double inclusion.

C-H3 – Macros [Banana]

Macros fit on a single line and contain a single statement.

A – Advanced

C-A1 – Constant pointers

Use const for pointed data that is not modified.

C-A2 – Typing

Use the most accurate type (size_t, ssize_t, unsigned...).

C-A3 – Line break at end of file [Banana]

Every file ends with a line break.

C-A4 – Static

Functions and globals only used in one file are declared static.
